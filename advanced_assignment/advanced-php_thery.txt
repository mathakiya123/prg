What is Abstraction?

Abstraction is one of the main pillars of Object-Oriented Programming (OOP).
It means hiding the complex implementation details and showing only the essential features of an object.

In simple terms:
You only show what an object does, not how it does it.

=> Purpose of Abstraction:

To simplify complex systems by breaking them into smaller, understandable parts.

To focus on essential operations rather than internal logic.

To achieve loose coupling between components (less dependency).

To enforce a common structure for multiple classes.

=> How Abstraction is Implemented in PHP:

In PHP, abstraction can be achieved in two ways:

Using Abstract Classes

Using Interfaces

=>Type hinting in PHP is a feature that allows developers to specify the expected data type of a function’s parameters, return values, and class properties. It helps PHP understand what type of value should be passed or returned, improving code reliability.

example
=>function add(int $a, int $b): int {
    return $a + $b;
}

Benefits of Type Hinting in PHP

1)Improves Code Reliability
Prevents invalid data types from being passed to functions.

2)Early Error Detection
Errors are caught at runtime before causing unexpected behavior.

3)Better Code Readability
Makes the function’s expected inputs and outputs clear.

4)Easier Maintenance
Developers can understand and modify code with less confusion.

5)Enhanced IDE Support
Enables better autocompletion, debugging, and static analysis.

6)Supports Object-Oriented Programming
Ensures correct object types are passed, improving OOP design.

7)Encourages Clean and Robust Code
Promotes disciplined coding practices and reduces bugs.

Email security is important because email is one of the most widely used communication methods and a common target for cyberattacks. Examples: PGP (Pretty Good Privacy), S/MIME.

**MVCArchitecture**
THEORY EXERCISE
1)Discuss the Model-View-Controller (MVC) architecture and its advantages in web
 development.
=> MVC (Model–View–Controller) is a software architectural pattern used to separate an application into three main components:

1.Model

2.View

3.Controller

It helps in organizing code cleanly, making it reusable, scalable, and easier to maintain.

1. Model

The Model represents the data and business logic of the application.

Responsibilities:

Interact with the database

Handle CRUD operations (Create, Read, Update, Delete)

Apply business rules / validations

Return data to the controller

2.View

The View is the presentation layer.

Responsibilities:

Display the user interface

Show data received from the controller

Should NOT contain business logic

3.Controller

The Controller handles the application flow.

Responsibilities:

Receive user requests

Call appropriate Model functions

Pass data to the View

Control navigation
